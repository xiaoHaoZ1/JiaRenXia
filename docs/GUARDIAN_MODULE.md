# 家人侠 守护模块设计

版本：V0.3  
日期：2026-10-02  
项目名称：家人侠  
文档类型：Guardian Module

---

## 1. 概述

守护模块来自独立项目 GuardMyFather，按 DEVELOPMENT_PLAN 第 6.5 节迁入家人侠，代码位于 `:feature:guardian`。**C3（2026-10-20）起守护已从家人侠移除，本模块仅由独立应用「守护侠」（`:guardianapp`）使用。**

适用场景：装在**被守护的人**（通常是独居的长辈）的手机上。如果这台手机长时间没有人使用，就先大声响铃并全屏提示确认；仍然无人响应时，自动拨打事先设定的**紧急联系人**。另外每天发送一条平安短信。

基本原则：

- 默认关闭，只有在这台手机上主动开启才会工作。
- 守护不联网：拨号和短信走运营商网络，只联系用户设定的紧急联系人。（App 不联网，见 AGENTS.md。）
- 核心指标是**不漏报**（真的出事时一定要拨出去）和**少误报**（睡觉、闲置时不乱响）。所有设计决策都服务于这两条。

## 2. 工作原理

```text
正常使用手机（解锁使用中） ──► 不计倒计时，只记“正在使用”
        │ 锁屏 / 熄屏结束使用                        │ 单次使用超过阈值仍兜底
        ▼                                           ▼
   从锁屏时刻开始倒计时                      使用中上限（= 正常阈值）到期
        │ 超过阈值（默认 8 小时）没有再用手机        │
        └───────────────┬───────────────────────────┘
                        ▼
              手机大声响铃 + 震动 + 全屏确认页
              倒计时（默认 2 分钟）等待确认
                    │
        ┌───────────┼───────────────┐
        │ 点“我没事”或解锁手机       │ 倒计时结束仍无人响应
        ▼                           ▼
   取消响铃，重新计时          自动拨打紧急联系人（尽量开免提）
                               拨号失败时补发一条紧急短信
```

## 3. 什么算“使用了手机”

| 行为 | 是否算活动 | 说明 |
|---|---|---|
| 解锁手机（指纹 / 人脸 / 密码 / 上滑） | 算 | 最可靠的“有人在操作”信号 |
| 解锁使用后再锁屏/熄屏 | 算 | 使用会话结束，从这一刻开始倒计时 |
| 接听来电、拨打电话 | 算 | 有些长辈主要用手机接打电话 |
| 在确认页点“我没事” | 算 | 手动确认平安 |
| 来消息或来电时屏幕亮一下又灭 | 不算 | 人晕倒时消息照样会来 |
| 未接来电响铃 | 不算 | 没人接听不代表人没事 |
| 开机、充电 | 不算 | 可能是自动发生的 |
| 守护自己拨出的报警电话 | 不算 | 通过“正在自拨号”标记、ALERTING 状态，以及“报警后 3 分钟内、且之后没有新来电的摘机”三重条件过滤 |

前提：被守护的手机必须设置锁屏（上滑、图案、密码、指纹或人脸都可以，不能是“无”），否则“解锁”信号不可靠。

## 4. 状态机

```text
DISABLED ──开启──► MONITORING ──到期──► CONFIRMING ──倒计时结束──► ALERTING ──拨出电话──► ALERTED
   ▲                  ▲                      │                                            │
   └──停止守护────────┴──── 任何活动 ─────────┴──────────────── 任何活动 ──────────────────┘
```

- MONITORING：正常监测。每次活动都重新计算截止时间。手机正在使用（解锁会话中）时不计倒计时，截止时间按“使用中上限”计算；锁屏后从锁屏时刻按正常阈值倒计时。
- CONFIRMING：已到期。响铃并全屏提示，等待“我没事”；期间任何解锁或通话同样会取消报警。
- ALERTING / ALERTED：已拨打紧急电话。之后一旦检测到活动，回到 MONITORING。

所有状态变化都只通过 `GuardEngine.handle(Event)` 这一个入口完成。引擎是纯 Kotlin，通过 `Clock` 和 `Ports` 接口与系统交互，全部状态流转都有 JVM 单元测试覆盖。

## 5. 计时规则（业务契约）

- **活动事件**：解锁（USER_PRESENT）；解锁会话之后的熄屏；非自拨号的摘机；点“我没事”；从系统使用记录中找回的解锁事件。
- **使用会话（inUse）**：解锁开始、锁屏结束。会话进行中不计倒计时（状态卡显示“正在使用”）；报警流程（CONFIRMING 及之后）中的熄屏只结束会话，**不算平安**、不取消响铃。
- **截止时间**：
  - 使用中：截止时间 = 上次活动 + 使用中上限（= 正常阈值）。一次使用持续超过阈值（视频循环、屏幕常亮）照样响铃；**使用中上限不受测试模式影响**。
  - 锁屏后：截止时间 = 上次活动 + 阈值（默认 8 小时，可选 1–24 小时；测试模式 30 秒）。严格模式，没有夜间豁免。
- **到达截止时间**：
  1. 先查系统使用记录，补回可能漏掉的解锁事件；
  2. 仍然过期，则进入 CONFIRMING：响铃、全屏通知，确认截止时间 = 现在 + 确认时长（默认 2 分钟；测试模式 15 秒）。
- **到达确认截止时间**：进入 ALERTING，拨打紧急联系人后进入 ALERTED，并写入事件日志。
  - 只拨一次，不重拨；
  - 拨号失败时补发紧急短信。
- **每日平安短信**：开启时每天在设定时刻（默认 09:00）发送，然后预约下一天。
- **任何活动事件**：回到 MONITORING；停止响铃；取消确认相关的闹钟；重新计算截止时间并挂闹钟。
- **开机、应用更新、修改时间**：
  - 如果守护已开启：确保前台服务在运行。
  - 截止时间已过：先进入响铃确认，不直接拨号。
  - 截止时间未过：按持久化的状态补挂所有闹钟。
- **看门狗**：每 30 分钟自查一次，确保服务存活、截止时间没有被系统吞掉，并自动修复；顺带做会话对账（见下）。守护已关闭时直接返回，不拉起服务。
- **会话对账（SyncSession）**：前台服务启动、看门狗自查、守护页可见时，引擎用 `PowerManager.isInteractive && !KeyguardManager.isKeyguardLocked` 校对“正在使用”标记：漏掉的解锁补记一次使用，漏掉的熄屏则保守地从上次活动按锁屏后阈值重新计时。对账只在 MONITORING 下进行，屏幕状态永远不能取消报警。对账后同时补挂截止、确认结束（只补挂、不在此拨号）、平安短信与看门狗闹钟，应对进程被杀后闹钟丢失（注：这里的“进程被杀”指系统回收，不是用户强行停止；强行停止见第 11 节）。
- **开启前提**：没有设定紧急联系人时不允许开启守护。

## 6. 可靠性设计

小米、vivo 等系统会主动杀后台，以下机制共同保证守护持续有效：

| 机制 | 作用 |
|---|---|
| 前台服务（specialUse 类型） | 动态注册屏幕亮灭、解锁广播（这些广播不能静态注册） |
| AlarmManager `setAlarmClock` | 到期、确认结束、平安短信的定时，不受 Doze 影响 |
| 看门狗闹钟 | 每 30 分钟自查服务是否存活、状态是否过期 |
| 开机与更新广播（含 LOCKED_BOOT_COMPLETED） | 重启或升级后继续守护 |
| Direct Boot | 重启后尚未解锁也能响铃、拨号：状态、配置、紧急联系人都存放在设备加密存储区 |
| 使用情况访问（可选） | 兜底：服务被杀期间漏掉的解锁事件，到期时从系统记录中找回 |
| 事件日志 | 最近约 300 条关键事件写入文件，可在守护页查看，便于排查 |
| 最低重要性状态通知渠道 | 常驻通知用 IMPORTANCE_MIN（无状态栏图标），关闭守护即消失 |

工程约定：

- 一切将来要发生的事都用 AlarmManager 落盘调度，禁止用进程内延时承担业务时序（进程随时可能被杀）。
- 广播接收器必须幂等、可重入、可乱序处理。

## 7. 权限与系统设置

### 7.1 运行时权限（开启守护时申请）

| 权限 | 用途 |
|---|---|
| 拨打电话（CALL_PHONE） | 无人确认时自动拨打紧急联系人 |
| 读取通话状态（READ_PHONE_STATE） | 接打电话算作使用 |
| 发送短信（SEND_SMS，可选） | 每日平安短信、拨号失败时的紧急短信；拒绝不影响开启守护 |
| 通知（POST_NOTIFICATIONS） | 守护状态与到期确认 |

### 7.2 特殊设置（在守护页的“权限清单”中逐项引导）

- 全屏通知（Android 14 及以上需要用户允许）
- 忽略电池优化
- 精确闹钟：Android 13 及以上自动获得；Android 12 需要手动开启
- 使用情况访问：可选，用于兜底

### 7.3 手机厂商设置（以小米 / 红米 / 澎湃 OS 为例）

| 设置项 | 为什么必须 |
|---|---|
| 自启动：允许 | 否则闹钟和广播无法唤起被杀掉的进程 |
| 省电策略：无限制 | 否则锁屏后进程被冻结，收不到屏幕广播 |
| 最近任务中给家人侠加锁 | 防止清理内存时被划掉 |
| 后台弹出界面：允许 | 到期时需要弹出全屏确认页 |
| 拨打电话：始终允许，并勾选“记住选择” | 否则每次拨号都会弹确认框，报警会失效 |
| 锁屏通知：允许 | 守护状态与确认通知要在锁屏上显示 |

### 7.4 与家人侠整体权限原则的关系

- 上述权限由守护模块的 Manifest 声明。这是 ARCHITECTURE 第 31 节“避免直接拨号高权限”的唯一例外，仅用于无人值守的紧急拨号。
- 不使用守护功能的手机不会被申请这些运行时权限。
- 守护模块不使用网络；App 整体不联网（AGENTS.md 约定）。

## 8. 隐私

- 守护的配置与状态保存在这台手机的设备加密存储区，**不包含在家人侠的备份文件中**，也被排除在系统云备份和设备间迁移之外（见 `backup_rules.xml`、`data_extraction_rules.xml`）；换机后需要重新设置。
- 日志和事件日志中的手机号一律打码（只保留前 3 位和后 4 位）。
- 每日平安短信的内容：最后一次使用手机的时间、距今多久、电量和是否在充电。只发给紧急联系人。
- 不读取通讯录全部内容：从通讯录选择紧急联系人时，使用系统联系人选择器，只读取所选的那一个号码。

## 9. 与家人侠的集成

- **模块边界**：`:feature:guardian` 不依赖 Hilt，不访问 Room，也不依赖 `:app`。它使用自己的轻量 ServiceLocator，以保证手机重启后、解锁前也能独立运行。
- **对外接口**：
  - 守护页入口组件 `GuardianTab`；
  - 由应用提供的“家人号码来源” `GuardianContactSource`：列出有在用号码的家人，只在选择紧急联系人时读取。
- **启动顺序**：应用启动时先初始化守护模块。如果用户尚未解锁，不启动生日提醒同步，也不访问 Room 和 DataStore，避免崩溃；收到解锁广播后再启动。
- **通知**：守护使用独立的通知渠道（`guardian_status_quiet`、`guardian_confirm`、`guardian_result`）和通知标签 `guardian`，与生日提醒互不干扰。状态渠道为 IMPORTANCE_MIN，不在状态栏显示图标；前台服务的状态通知不带标签（与 startForeground 共用 id），关闭守护即消失。点击守护通知会回到家人侠主界面。
- **界面**：守护页使用 `:core:designsystem` 中的统一主题与组件，内部分三屏：
  - 主页：未开启时依次是功能说明、紧急联系人、守护设置、权限进度和“开启守护”；开启后显示状态卡（正在使用/上次使用、上次锁屏、距离响铃检查倒计时、下次平安短信）、等待确认或已报警时的操作卡，以及“停止守护”。使用中没有倒计时，显示“锁屏后开始计时”。
  - 权限清单：每项显示状态与“去开启”按钮，另有手机厂商设置入口。
  - 事件日志。
- **开启流程**：先申请运行时权限；拒绝“拨打电话”权限时不能开启；最后展示后果说明，由用户确认。
- **测试工具**：立即响铃、立即发送平安短信、测试拨打，只在测试模式下显示，每次操作前都要二次确认。
- **锁屏确认页**：强制浅色、高对比度、超大按钮（“我没事” / “立即呼叫”），在锁屏之上显示。

## 10. 在长辈手机上的设置步骤

1. 在长辈手机上安装守护侠。如果之前装过 GuardMyFather，先在其中停止守护，再卸载它，避免两个应用重复报警。
2. 守护侠没有家庭档案：紧急联系人从系统通讯录选择或手动输入。
3. 打开守护侠，选择紧急联系人：从系统通讯录选择，或手动输入。
4. 按需调整无活动阈值（默认 8 小时，可选 1–24 小时）、确认时长（默认 2 分钟）、每日平安短信（默认 09:00）。
5. 按“权限清单”逐项授权，并完成第 7.3 节的厂商设置。
6. 确认手机已设置锁屏，然后点“开启守护”。
7. 用测试模式按第 11 节验证一遍，验证完成后务必关闭测试模式。

## 11. 测试模式与真机回归清单

测试模式：无活动阈值 30 秒，确认时长 15 秒，守护页会显示醒目提示。

**注意**：测试会真实地响铃、拨打电话、发送短信。请使用自己可以接听的号码作为测试紧急联系人，并提前告知对方。

修改引擎、闹钟、服务相关代码后，必须在真机上完成：

1. 测试模式下：
   - 开启后使用中显示“正在使用”，不计倒计时；
   - 锁屏后开始倒计时，静置 30 秒后响铃并出现全屏确认页；
   - 点“我没事”回到守护中、重新计时；
   - 不操作，15 秒后自动拨出（看到系统通话界面）；
   - 关闭守护后状态通知消失，通知栏只保留一条状态通知（且不在状态栏显示图标）。
2. 只按电源键亮屏再熄灭（不解锁），不重新计时；解锁后再锁屏，重新计时。
3. 拨打或接听任意电话后，重新计时。
4. 进程结束要区分三种方式，按 Android 官方行为验证，引擎不为绕过强行停止做特殊处理：
   - **强行停止**（设置 → 应用信息 → 强行停止，或 `adb shell am force-stop`）：应用整体进入停止状态，已注册的闹钟、广播、定时任务全部失效，看门狗也无法拉起——这是系统规定，不是缺陷。验证方式：强停后由用户重新打开应用，守护须自动恢复（前台服务重启、按持久化状态补挂闹钟、到期仍能响铃）。
   - **系统回收**（内存不足杀死进程）：闹钟仍然有效，到点照常进入响铃确认。
   - **最近任务划掉**：只结束界面和进程，不等于强行停止；到点仍应响铃（小米需先完成白名单设置）。
5. 重启手机、不解锁：日志中有开机恢复记录，到期仍能响铃。
6. 每日平安短信能发到测试号码，且号码在日志中是打码的。
7. 未设置紧急联系人时无法开启守护。

## 12. 局限性

- 手机没电、欠费、取出 SIM 卡、开飞行模式时无法报警。每日平安短信可以帮助侧面发现：哪天没收到，就该打电话问问。
- 设置了 SIM 卡 PIN 码的手机，重启后要先输入 PIN 才能拨号，建议去掉 SIM PIN。
- 报警电话未接通时不会自动重拨（产品决定）。
- 用户在系统设置里“强行停止”应用后，闹钟与守护不再生效，直到用户重新打开应用——这是 Android 的规定行为，不为此做引擎上的绕行。
- 系统大版本升级后，建议重新检查一遍权限清单。

---

## 13. 扩展点（未实现）

- 未接通时重拨或轮流拨打多位联系人：需要 READ_CALL_LOG 判断是否接通，并挂“回查闹钟”。
- 夜间时段或节假日规则：在 `TimeRules.computeDeadline` 中加入时间窗顺延，必须补单元测试。
- 远程指令（短信控制）：需要 RECEIVE_SMS 和指令鉴权，涉及隐私条款，需单独评估。
