## 发布测试版

1. **打包**：在 worktree 的 `apps/android` 跑 `gradlew.bat :app:assembleDebug`。核对 `app/build/outputs/apk/debug/output-metadata.json`：applicationId 为 `com.jiarenxia.app.debug`、versionCode 56、versionName `2.2.0-debug`。
2. **核对签名**：用 `adb install -r` 覆盖安装到真机上已有的 `com.jiarenxia.app.debug`（2.1.3-debug）。安装成功说明签名一致；如果报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` 就停下来报告，不要卸载任何东西。正式版 `com.jiarenxia.app` 和里面的真实数据一律不碰。
3. **真机走查**：只在测试版里操作，名字用合成的 ASCII（比如 TestMom）。每一步截图存到 `runtime/`：
   - 打开一个家人的详情页，「关于TA」卡片应在"重要日期"和"TA 的事"之间；空状态下点「尺码」，添加鞋码 37。
   - 再添加一次鞋码，填 38：弹框应提示「原来记的是 37，保存后会替换」；保存后只剩一条「鞋码 38」。
   - 点「鞋码 38」进入编辑：不应出现"哪一项"的选择，输入框标题是「鞋码」；然后删除这一条。
   - 在测试版的「我的 → 外观与字号」把字号拉到 160%，打开添加弹框，点输入框弹出键盘：正文要能上下滚动，输入框和「保存」都能看到、能点。走查完把字号调回原值。
   - 用自定义分类（分类名加内容）添加一条，再编辑一次。
   - 把这个人标为已故后，添加时没有「尺码」和「想要的」两个分类。
   - 删除这个人：确认提示里要出现「N 条「关于TA」记录」。
   - 发现任何问题就停下来报告，不要自己改代码。
4. **上传与官网**（走查全部通过、并经用户同意后）：
   - 计算新包的大小和 SHA-256；把 `app-debug.apk` 上传到 R2 桶 `jrx-download`，文件名 `jiarenxia-beta-2.2.0.apk`（`wrangler r2 object put`，加 `--remote`）。上传后用 `curl -I https://dl.jiarenxia.com/jiarenxia-beta-2.2.0.apk` 核对大小一致。
   - 修改 `apps/web/src/site.ts` 的 `APK_BETA`：version 改为 `"2.2.0-debug"`，sizeBytes 和 sha256 填新值，file 指向 `jiarenxia-beta-2.2.0.apk`。**旧的 sha256（`e3b0c442…b855`）是空文件的哈希，本来就是错的**，这次一并改正。正式版的 `apkVersion`、`apkVersionCode` 不动。
   - 在 `apps/web` 跑 typecheck、build、e2e，全部通过后执行 `jrx.cmd web-deploy`；打开官网下载页，核对测试版的版本号、大小、校验值和下载链接都正确。
5. **收尾**：site.ts 的改动提交到 `feature/beta-2.2.0` 并推送；在主工作区快进合并到 main，推送 main；删除已合并的 worktree 和本地、远端分支。在本文末尾补一段"发布结果"（签名核对、走查截图路径、上传与部署结果、合并后的 main 提交号），或者告诉用户已完成。
