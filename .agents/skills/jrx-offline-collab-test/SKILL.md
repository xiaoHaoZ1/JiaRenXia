# 家人侠离线协作验收（双模拟器）

前置：`jrx-cloud-android-test`（双机已起、同版 APK）。A=emulator-5554 汇总者，B=emulator-5556 成员。只用合成数据（ASCII 名）；真实资料、签名密钥绝不入库。

## 发送/接收必须走真实入口

- 发送：家庭页 → 共享与连接 → 发布确认版/发回补充 → 输密码 → 系统 sharesheet。包文件落在 `cache/collab/家人侠-*.jrxb`。
- 中转：包不出 App 沙箱外其他 App 可读区，宿主取件用
  `adb -s <s> exec-out run-as com.jiarenxia.app cat "cache/collab/<文件>" > /tmp/x.jrxb`
  再 `adb -s <对端> push /tmp/x.jrxb /sdcard/Download/`。
- 接收：App 内“接收协作包”→ 系统文件选择器(SAF) 选 Download 里的 .jrxb → 密码 → 审阅页 → 逐项裁决 → 确认接收。
- 禁止改库/调内部服务代替收发；每步用 `run-as` 拉 DB 或 dumpsys 核验实际落库。

## 验收场景要点（已验证行为，2026-10 验收）

1. **两轮往返**：发布→接收选“我是谁”→成员改资料发补充→汇总者汇入→再发布→再接收。分次补充不重复建人；已汇入/未汇入改动能区分。
2. **并发分歧**：同字段双改（备注/电话/生日）→ 接收页“需要确认”，未裁决“确认接收”禁用；逐项采用/保留后落库正确。删除 vs 修改 → 整人去留单项裁决。
   - 换号特例：基准号 A 双端分别替换成 B、C → 两个新号都应成“需要确认”项（修复见 FamilyRevisionPlan 换号分歧分支）；原“两号并存即通过”是错的。
3. **重复/乱序**：同包再选 → “已经接收过了”拒收；旧确认版 → “不比已接收的新”拒收；基于旧确认版的**合法**补充不一概拒收——进入三方比较，与新版同字段改动按“需要确认”裁决，不静默覆盖/回退。
4. **中断保护**：接收页草稿退出重开/force-stop 重启可续；取消分享不留悬挂；仅本机人物可重新纳入；私人记录/头像/“我”收发后不变；接收前副本在 我的→数据管理 可找回并恢复成接收前资料。
5. **通讯录**：系统联系人选择器选号回填；同一人物规范化重复选同号应阻止/复用；不同家人允许同号。**完全空白的新电话行直接忽略**（自动裁剪不报错）；**已有行清空、或号码为空但填了附加内容（标签/备注）→ 行内报错「请填写号码，或删除这条电话」并定位**。文字删除入口、固定保存按钮可用。
6. **关系图**：能出有效导出图（文件存在、查看器可打开）为取证标准；布局美观度由主审单独定规格，**不**把当前渲染当正确范例。

## 取证习惯

- 每项记：操作、预期、实际、截图路径、DB/日志证据；产物按轮次放 `~/jrx_accept/rN/`。
- 拒收/冲突类的关键画面要 screencap + run-as 拉库双重证据。
- 一台装 debug 一台照旧版本会带签名冲突：两台必须装同一份 APK（debug 签名随机器而异）。
